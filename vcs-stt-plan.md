# ВКС + Speech-to-Text: План кратчайшей траектории

> Внутренний стартап. Цель — рабочий MVP за минимальное время.

---

## Стек

| Слой | Выбор | Почему |
|------|-------|--------|
| Видео/аудио | **LiveKit** (open-source SFU) | Бесплатный, self-hosted, SDK для веба и мобилок, встроенный audio egress |
| Speech-to-text | **Deepgram** или **Whisper API** | Deepgram — real-time стриминг из коробки, низкая задержка. Whisper — fallback если нужен self-hosted |
| Бэкенд | **Node.js + Fastify** | Быстрый старт, хорошая поддержка WebSocket, SDK LiveKit есть |
| Фронтенд | **React + LiveKit React SDK** | Готовые компоненты для видео, минимум кастомного кода |
| БД | **PostgreSQL** | Хранение транскриптов, пользователей, истории |
| Очередь | **BullMQ (Redis)** | Асинхронные задачи: пост-обработка транскриптов, webhooks |
| Деплой | **Docker Compose** | Для внутреннего стартапа — достаточно, масштабируется позже |

## Фазы

### Фаза 1 — Скелет (2-3 дня)

**Результат:** два человека могут войти в комнату, видеть/слышать друг друга.

- [ ] Docker Compose: LiveKit server + Redis + PostgreSQL
- [ ] Бэкенд: генерация токенов LiveKit, создание комнат (REST API)
- [ ] Фронтенд: страница входа → видеокомната (LiveKit React SDK)
- [ ] Базовая аутентификация (JWT, без OAuth пока)

### Фаза 2 — Speech-to-Text (2-3 дня)

**Результат:** во время звонка появляются субтитры в реальном времени.

- [ ] Audio track → WebSocket → Deepgram Streaming API
- [ ] Транскрипт отображается в UI как субтитры (с именем говорящего)
- [ ] Сохранение полного транскрипта в PostgreSQL после завершения звонка
- [ ] Страница просмотра истории транскриптов

### Фаза 3 — Интеграции (3-4 дня)

**Результат:** звонок связан с рабочими процессами компании.

- [ ] **Календарь** — создание/планирование звонков через Google Calendar API или CalDAV
- [ ] **Telegram-бот** — уведомления о начале звонка, ссылка для входа, саммари после
- [ ] **Webhook-система** — POST на внешний URL при событиях (звонок начался/закончился, транскрипт готов)
- [ ] **Экспорт транскрипта** — Markdown/PDF/JSON по API

### Фаза 4 — Польза от транскриптов (2-3 дня)

**Результат:** транскрипты не просто лежат, а работают.

- [ ] Автосаммари через Claude API (краткое резюме встречи)
- [ ] Извлечение action items / решений из транскрипта
- [ ] Поиск по истории транскриптов (полнотекстовый)
- [ ] Отправка саммари + action items в Telegram/Slack после звонка

## Ключевые решения

1. **LiveKit вместо своего WebRTC** — экономит 2-3 недели. Audio egress позволяет снимать аудиопоток на сервере без костылей в браузере.

2. **Deepgram вместо self-hosted Whisper** — для MVP задержка критична, Deepgram даёт ~300ms. Self-hosted Whisper можно добавить позже как альтернативный провайдер.

3. **Монорепо (packages/)** — фронт и бэк рядом, общие типы, один `docker-compose up`.

4. **BullMQ для интеграций** — webhooks и уведомления не блокируют основной поток. Если Telegram/Calendar API тормозит — это не ломает звонок.

5. **Claude API для саммари** — не изобретаем NLP, просто отправляем транскрипт в Claude и получаем структурированное резюме.

## Риски и митигация

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| Deepgram дорого при масштабе | Средняя | Заложить абстракцию STT-провайдера, добавить Whisper позже |
| LiveKit сложно деплоить | Низкая | Есть Docker-образ, для внутреннего — хватит одного сервера |
| Качество STT на русском | Средняя | Deepgram поддерживает русский; тестировать рано, переключиться на Whisper large-v3 если плохо |
| Безопасность аудио/видео | Средняя | LiveKit поддерживает E2E encryption, включить на фазе 5 |

## Что НЕ делаем в MVP

- Мобильное приложение (только веб)
- Запись видео (только аудио-транскрипт)
- SSO/LDAP (простой JWT)
- Шифрование E2E (добавим позже)
- Масштабирование на >50 одновременных пользователей
