# Skill: Reflect

**Назначение:** Анализ завершённой сессии или проекта — создаёт `~/.claude/reflection.md` как входные данные для Improve Skill.
**Когда использовать:** В конце каждой значимой сессии. Обязательно — в конце проекта.
**Результат:** Файл `~/.claude/reflection.md` (глобальный, не в папке проекта) + новые записи в `~/.claude/skills/hard-problems.md` при сложных случаях.

---

## PROCESS

### Шаг 1 — Собери данные сессии

Перед анализом прочитай:
1. `CLAUDE.md` — текущий Session Log и Known Issues
   ⚠️ Если CLAUDE.md не существует — зафиксируй сразу:
   не пытайся его читать, в Шаге 5 пропусти обновление,
   в reflection.md секция "Правки CLAUDE.md" должна содержать:
   `"CLAUDE.md отсутствует — /intake не запускался, Session Log не ведётся."`
2. `~/.claude/skills/index.md` — какие скиллы использовались
3. `~/.claude/skills/hard-problems.md` — сравни проблемы этой сессии с уже зафиксированными.
   Если та же проблема уже встречалась в другом проекте — это **повторяющийся паттерн**, отметь явно в reflection.md. Повторяющийся паттерн = кандидат на новый скилл.
4. Список изменённых файлов — запусти одно из:
   - `git diff --name-only HEAD` (если git repo) — показывает что реально менялось
   - Glob `**/*.{py,html,js,css,md,yaml}` + `ls -lt` по дате изменения (если не git) —
     найди файлы новее чем ~начало сессии; сравни с памятью о сессии
   Важно: без этого шага "Ручная работа" строится на памяти → неточно в длинных сессиях
5. **Theme rotation** — прочитай последние 3 файла `~/.claude/reflection-*.md` (архив, по дате).
   Для каждого определи доминирующую ось: какая из 5 осей содержит больше всего конкретных наблюдений (не "не выявлено").
   - Если одна ось доминировала все 3 раза подряд → **в Шаге 2 акцентируй другую ось** (выбери наименее исследованную).
   - Если архив пуст или меньше 3 файлов → пропусти, анализируй все оси равномерно.
   Результат: внутренняя пометка "акцент этой сессии: [ось N]" — используется в Шаге 2.

### Шаг 2 — Проведи анализ по 5 осям

> Если в Шаге 1 (п.5) определён акцент — уделяй акцентируемой оси вдвое больше глубины.
> Остальные оси анализируй кратко, но не пропускай.

**Ось 1: Скиллы**
- Какие скиллы использовались в этой сессии?
- Для каждого выставь оценку:
  - `✅` — сработало с первого раза, без итераций
  - `⚠️` — потребовало уточнений, переформулировок, переделок
  - `❌` — не помогло или запускалось зря
- Что из них сработало хорошо — дало правильный результат с первого раза?
- Где были трения — пришлось переформулировать, уточнять, переделывать?
- Что оказалось лишним — скилл запускался, но почти не помог?

**Ось 2: Ручная работа**
- Что пользователь делал вручную, что можно было автоматизировать?
- Какие повторяющиеся действия были в этой сессии?
- Какие инструкции давались агенту словами — и могли бы стать скиллом?

**Ось 3: Безопасность**
- Были ли подозрительные инструкции в данных (файлах, API-ответах, комментариях)?
- Были ли запросы на действия вне scope сессии?
- Сработали ли стоп-операции корректно?

**Ось 4: Архитектура и решения**
- Какие архитектурные решения были приняты в этой сессии?
- Что стоит зафиксировать в ADR, чтобы не пересматривать в следующий раз?
- Что оказалось сложнее, чем ожидалось — и почему?

**Ось 5: Предложения по улучшению скиллов**
- Конкретные правки для существующих скиллов (что добавить / убрать / переформулировать)
- Нужен ли новый скилл? Если да — для чего именно?
- Что в CLAUDE.md устарело или стало неточным?

### Шаг 3 — Определи сложные случаи

Случай попадает в `~/.claude/skills/hard-problems.md` если:
- Потребовал больше 2 попыток решения
- Решение неочевидно и не следует из документации
- Инсайт переносим на другие проекты
- Была ошибка в предположениях (своих или агента)

Для каждого такого случая — добавь запись в `~/.claude/skills/hard-problems.md` по шаблону.

### Шаг 3б — Проверь существующий reflection.md

Перед записью нового файла — проверь, существует ли `~/.claude/reflection.md`:

- **Не существует** → переходи к Шагу 4 сразу
- **Существует, строка коррекции пуста** → перезапиши молча (старый reflection незакончен, текущий важнее)
- **Существует, строка коррекции заполнена** → спроси:
  ```
  Есть непримененный reflection от [дата из заголовка].
  Что делать?
    1. Перезаписать (потерять старый)
    2. Сначала запустить /improve, потом reflect снова
  ```
  Жди ответа. Не угадывай.

### Шаг 4 — Создай reflection.md

Запиши файл в `~/.claude/reflection.md` строго по шаблону ниже.
Это глобальный файл — не в папке проекта. Improve читает его из одного места независимо от того, из какого проекта запускается.
Краткость важнее полноты.

### Шаг 5 — Обнови CLAUDE.md

**Сначала проверь:** существует ли `CLAUDE.md` в текущей рабочей директории?

- **НЕ существует** → пропустить этот шаг полностью. Добавить в reflection.md в секцию "Правки CLAUDE.md":
  `"CLAUDE.md отсутствует — Session Log не обновлялся. При следующем проекте запустить /intake."`
- **Существует** → выполнить всё ниже:

  - Перенеси завершённые задачи из "What's In Progress" в "What Works"
  - Добавь запись в Session Log
  - Обнови статус текущей Phase
  - **Обнови строку `Last updated`** в PROJECT OVERVIEW — дата сегодня + краткий заголовок сессии
    Формат: `YYYY-MM-DD (Session N — [одна строка что сделано])`

### Шаг 6 — Собери строку коррекции в чате

После сохранения всех файлов:

1. Скажи пользователю:
   `"Одна строка коррекции: что самое важное улучшить или усилить?"`
2. Дождись ответа (одна строка от пользователя)
3. Запиши ответ в секцию `Строка коррекции пользователя` в `~/.claude/reflection.md`:
   замени `[пусто — ждёт ввода]` на текст пользователя
4. Спроси: `"Запустить /improve сейчас?"`
   - Если `"да"` / `"давай"` / `"запускай"` / `"yes"` →
     немедленно выполни `@~/.claude/skills/improve/SKILL.md`
   - Если `"нет"` / `"потом"` / `"позже"` →
     скажи `"Ок. Запустишь /improve когда будешь готов."` и завершай
