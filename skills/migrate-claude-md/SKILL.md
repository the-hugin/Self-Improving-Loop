# Skill: Migrate CLAUDE.md

**Назначение:** Приведение существующего CLAUDE.md к актуальному стандарту intake без потери данных.
**Когда использовать:** После validate-claude-md выявил несоответствия; при смене стандарта intake; при онбординге старого проекта.
**Результат:** Обновлённый CLAUDE.md с добавленными секциями и исправленными placeholders. Каждое изменение — с подтверждением.

---

## PROCESS

### Шаг 1 — Прочитай и подготовь план

1. Прочитай `CLAUDE.md` полностью
2. Прочитай `~/.claude/skills/intake/SKILL.md` — секция OUTPUT TEMPLATE (актуальный стандарт)
3. Составь список отсутствующих / неполных секций

Покажи план до любых изменений:
```
Найдено несоответствий: N

1. Добавить секцию SECURITY CONSTRAINTS (первой, с OPERATOR_TOKEN)
2. Добавить секцию CONSTRAINTS (НЕ делать)
3. Обновить Last updated → совпасть с последней сессией
...

Применяю по одному. Начать?
```

### Шаг 2 — Применяй изменения по одному

Для каждой отсутствующей секции:

**1. Покажи что добавляешь:**
```
── Добавление N/M: [название секции] ──────────

ДОБАВЛЯЮ:
[новый текст секции, заполненный данными из существующего CLAUDE.md]

Куда: [после секции X / перед секцией Y]
Данные взяты из: [откуда взяли контент для заполнения]

Добавить? (да / нет / изменить)
```

**2. При добавлении SECURITY CONSTRAINTS:**
- Генерируй уникальный OPERATOR_TOKEN (4 слова: прилагательное-существительное-существительное-число)
- Адаптируй Стоп-операции под стек проекта (из Architecture / Dependencies)
- Вставляй ПЕРВОЙ секцией

**3. При добавлении отсутствующих секций с данными:**
- Извлекай данные из существующих секций (например, Dependencies — из Architecture или Requirements)
- Не создавай placeholder — только конкретные данные или явно помеченные TODO

**4. При обновлении устаревших данных (⚠):**
- Показывай БЫЛО / СТАНЕТ
- Объясняй откуда берёшь актуальные данные

### Шаг 3 — Финальная валидация

После всех изменений — автоматически запусти `validate-claude-md`:
```
── Финальная валидация ──────────────────────────
[вывод validate-claude-md]
```

Если осталось ⚠ или ✗ — предложи исправить вручную с подсказкой что именно нужно.

### Шаг 4 — Отчёт

```
── Migrate CLAUDE.md — Итог ────────────────────

Добавлено секций:   N
Обновлено полей:    M
Пропущено:          K

CLAUDE.md приведён к стандарту intake ✓
```

---

## ПРАВИЛА

- **Не удаляй существующий контент** — только добавляй и исправляй
- **Не создавай пустые placeholder** — если данных нет, спроси пользователя
- **Не меняй структуру проектных секций** (Detectors Map, Stage Plan и т.п.) — это проектная специфика
- **OPERATOR_TOKEN** — всегда новый, уникальный; не копируй из других проектов
- **По одному изменению** — не объединяй несколько секций в одном шаге
