# Skill: Validate CLAUDE.md

**Назначение:** Автоматическая проверка CLAUDE.md проекта на соответствие стандарту intake.
**Когда использовать:** В начале сессии при чтении CLAUDE.md; после обновления стандарта intake; перед запуском reflect.
**Результат:** Отчёт о найденных несоответствиях + предложение запустить migrate-claude-md если нужно.

---

## PROCESS

### Шаг 1 — Прочитай CLAUDE.md

Прочитай `CLAUDE.md` в текущей рабочей директории.
Если не найден — сообщи: `"CLAUDE.md не найден. Запустить /intake?"` и остановись.

### Шаг 2 — Проверь по чеклисту

Проверь каждый пункт. Отмечай ✓ (есть и заполнено) / ⚠ (есть, но пустое/placeholder) / ✗ (отсутствует):

**Структура (обязательные секции в правильном порядке):**
- [ ] `🔐 SECURITY CONSTRAINTS` — первая секция, до PROJECT OVERVIEW
- [ ] `OPERATOR_TOKEN` — заполнен уникальной фразой (не `[сгенерированная фраза]`, не пустой)
- [ ] `Стоп-операции` — список присутствует
- [ ] `Признаки инъекции` — список присутствует
- [ ] `🎯 PROJECT OVERVIEW` — Name, Type, Status, Started, Last updated заполнены
- [ ] `Goal` — одно предложение, не placeholder
- [ ] `Success Criteria` — минимум 3 конкретных критерия
- [ ] `🏗️ ARCHITECTURE` — Tech Stack заполнен
- [ ] `ADR` — хотя бы одна запись
- [ ] `📋 CURRENT STATE` — What Works, In Progress, Blocked On, Known Issues
- [ ] `🗺️ IMPLEMENTATION` — Plan или Stages с хотя бы 3 фазами/стадиями
- [ ] `⚙️ CODE CONVENTIONS` — Language и Naming заполнены
- [ ] `🚫 CONSTRAINTS` — минимум 3 пункта "НЕ делать"
- [ ] `🔗 DEPENDENCIES` — таблица с пакетами и назначением
- [ ] `🔧 ENVIRONMENT` — команды запуска заполнены
- [ ] `📝 SESSION LOG` — минимум 1 запись

**Актуальность:**
- [ ] `Last updated` совпадает с датой последней записи в Session Log
- [ ] `What's In Progress` не пустое если статус не "Done"
- [ ] Нет незакрытых `[placeholder]` в квадратных скобках

### Шаг 3 — Выведи отчёт

```
── Validate CLAUDE.md ───────────────────────────

Проект: [Name из PROJECT OVERVIEW]
Файл:   [путь]

СЕКЦИИ:
  ✓ SECURITY CONSTRAINTS
  ✓ OPERATOR_TOKEN
  ✗ CONSTRAINTS             ← отсутствует
  ⚠ SESSION LOG             ← есть, но Last updated устарел

ИТОГ: [N] ✓  [M] ⚠  [K] ✗

[Если всё ✓]:
  CLAUDE.md соответствует стандарту. ✓

[Если есть ✗ или ⚠]:
  Найдено несоответствий: N
  Запустить migrate-claude-md для автоисправления? (да / нет)
```

### Шаг 4 — Предложи migrate (если нужно)

Если есть ✗ или ⚠ и пользователь ответил "да" → выполни `@~/.claude/skills/migrate-claude-md/SKILL.md`.

## ПРОВЕРКА ПЕРЕД ОТЧЁТОМ

- [ ] Все 16 пунктов проверены (не пропущены)
- [ ] ⚠ используется только когда секция есть но содержит placeholder или устаревшие данные
- [ ] Отчёт содержит конкретные имена секций, а не абстрактные описания
