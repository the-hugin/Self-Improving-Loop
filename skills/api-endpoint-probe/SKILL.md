# Skill: API Endpoint Probe

**Назначение:** Быстрая разведка параметров API-эндпоинта перед реализацией — выяснить что реально работает (фильтры, пагинация, лимиты, auth) через серию минимальных тестовых запросов.
**Когда использовать:** Когда предстоит интеграция с новым эндпоинтом и неизвестно: какие параметры он принимает, какой тип пагинации поддерживает, работает ли без обязательных фильтров, каков реальный лимит ответа.
**Результат:** Таблица "что работает / что не работает" + рекомендованный способ вызова для реализации.

---

## PROCESS

### Шаг 1 — Собери исходные данные

Спроси у пользователя (если не указано в запросе):
1. URL или шаблон эндпоинта (например: `GET /v1/trades?market={id}`)
2. Есть ли auth — API key, Bearer token, cookie?
3. Какая цель: пагинация по всем записям / фильтрация / разовый fetch?
4. Есть ли известные параметры из документации? (даже частичные)

### Шаг 2 — Составь план зондирования

Сформируй минимальный набор из 3–5 тестовых запросов:

| # | Цель | Параметры | Ожидаемый результат |
|---|------|-----------|---------------------|
| 1 | Базовый вызов без фильтров | — | Проверить: работает ли вообще, какой формат ответа |
| 2 | Лимит страницы | `limit=1` / `size=1` | Есть ли параметр, как называется |
| 3 | Пагинация cursor | `cursor=` / `next=` / `after=` | Какой тип пагинации |
| 4 | Пагинация по времени | `startTs=` / `after=` / `since=` | Работает ли timestamp-фильтр |
| 5 | Фильтр по entity | `market=X` / `user=Y` | Обязателен ли фильтр |

Покажи план пользователю — жди "да" перед выполнением.

### Шаг 3 — Выполни зондирующие запросы

Для каждого запроса из плана:
1. Покажи точный запрос перед выполнением
2. Выполни через `requests` (Python) или `curl` — в зависимости от окружения
3. Зафиксируй: статус, размер ответа, ключевые поля

```python
# Шаблон для Python-зондирования
import requests, json

BASE = "https://api.example.com"
HEADERS = {"Authorization": "Bearer TOKEN"}  # если нужен auth

def probe(path, params=None):
    r = requests.get(BASE + path, headers=HEADERS, params=params)
    print(f"{r.status_code} | {len(r.content)}b | {path}?{r.request.path_url.split('?',1)[-1]}")
    try:
        data = r.json()
        # показать структуру первого элемента
        if isinstance(data, list) and data:
            print(json.dumps(data[0], indent=2)[:300])
        elif isinstance(data, dict):
            print(json.dumps({k: type(v).__name__ for k, v in data.items()}))
    except:
        print(r.text[:200])
    return r
```

### Шаг 4 — Зафиксируй результаты

После всех запросов выведи итоговую таблицу:

```
── Результаты зондирования: [эндпоинт] ────────────────

| Параметр        | Работает? | Как использовать              |
|-----------------|-----------|-------------------------------|
| без фильтров    | ✅/❌     | [наблюдение]                  |
| limit/size      | ✅/❌     | limit=N или size=N            |
| cursor-пагинация| ✅/❌     | поле next_cursor в ответе     |
| startTs фильтр  | ✅/❌     | startTs=unix_ms               |
| user фильтр     | ✅/❌     | обязателен / опционален       |

Рекомендованный вызов для реализации:
  GET [path]?[param1=val]&[param2=val]
  Пагинация: [cursor / offset / timestamp / нет]
  Лимит: [реальный лимит страницы]
  Примечания: [что не работает или неожиданно]
```

### Шаг 5 — Обнови документацию

Если в проекте есть `CLAUDE.md`:
- Добавь находки в "Known Issues" или отдельную секцию "API Notes"
- Пометь какой тип пагинации подтверждён — чтобы не перепроверять

---

## ПРАВИЛА

- Не делай больше 10 запросов без явного согласия пользователя
- Не используй production-мутирующие методы (POST/DELETE) без явного указания
- Если эндпоинт возвращает 401/403 — сразу сообщи, не угадывай auth
- Если параметр не задокументирован но работает — отметь как "undocumented, проверить в следующей версии API"
