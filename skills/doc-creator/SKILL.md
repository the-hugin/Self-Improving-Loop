# Skill: doc-creator

**Назначение:** Универсальный онбординг для создания любых структурированных документов — портфельные гайды, сравнительные таблицы, обучающие материалы, каталоги, отчёты, презентации. Вывод: HTML→PDF, DOCX, Slides.
**Когда использовать:** Пользователь просит создать документ, гайд или презентацию на основе источников (docx, PDF, сайт, данные). Любой тип — не только продуктовый.
**Результат:** Согласованная структура документа + выбранный дизайн + готовый генератор или файл.

---

## PROCESS

### Шаг 1 — 4 универсальных вопроса (задать все, не угадывать)

Задай пользователю эти 4 вопроса перед любой работой:

1. **Тип документа:** что это по сути?
   (гайд / каталог / сравнение / отчёт / обучение / иное — пусть опишет)

2. **Аудитория:** кто читает и каков их бэкграунд?
   (роль, уровень экспертизы, что уже знают, что не знают)

3. **Цель читателя:** что он должен уметь / знать / решить после прочтения?
   (одно конкретное действие или состояние)

4. **Формат вывода:** HTML→PDF / DOCX / Slides (Google, PowerPoint) / Web-страница?

> Не переходи к Шагу 2, пока не получены все 4 ответа.
> Если пользователь отвечает частично — уточни недостающее.

---

### Шаг 2 — Дизайн-выбор (показать варианты, дождаться ответа)

Покажи варианты явно — не выбирай по умолчанию:

```
Выбери стиль документа:

A) Compact   — плотная вёрстка, много контента на странице,
               минимум декора. Подходит для справочников,
               технических сравнений, внутренних материалов.

B) Rich      — крупные блоки, визуальные акценты, иконки,
               цветовые выделения. Подходит для продуктовых
               гайдов, клиентских материалов, onboarding.

C) Sectioned — цветные обложки-разделители между секциями,
               каждый раздел начинается с новой страницы.
               Подходит для многотемных гайдов, каталогов,
               обучающих курсов.

D) Custom    — опиши стиль словами или прикрепи референс.
```

**Правило:** для вариантов B, C, D — вызвать скилл `frontend-design`
для проработки дизайн-системы (цвета, типографика, компоненты)
**до** написания кода. Не импровизировать дизайн в процессе генерации.

> Дождись явного ответа (A / B / C / D + описание для D).

---

### Шаг 3 — Предложи структуру документа

На основе ответов из Шага 1 — предложи структуру:

- Список разделов с названиями
- Тип блока в каждом разделе: карточка / таблица / список / нарратив / смешанный
- Глубину каждого раздела (количество полей / уровень детализации)

**Правила:**
- Не используй фиксированный шаблон — структура определяется типом документа
- Если тип = каталог/гайд → предложи карточечную структуру с полями под аудиторию
- Если тип = сравнение → предложи матрицу или параллельные колонки
- Если тип = обучение → предложи модульную структуру (тема → теория → пример → вопрос)
- Если тип = отчёт → предложи executive summary + секции + appendix

> Покажи структуру как список. Дождись "ок" или правок.
> Не начинай генерировать контент до подтверждения структуры.

---

### Шаг 4 — Источники и данные

Выясни что есть:

```
□ Какие источники предоставлены?
  - DOCX / текстовые файлы
  - PDF (важно: image-based или текстовый? проверь get_text())
  - Сайт (URL для скрапинга)
  - Структурированные данные (CSV, JSON, таблицы)
  - Только устные инструкции / память сессии

□ Есть ли брендинг?
  - Логотип / гайдлайн бренда → применить
  - PDF с примерами → запустить extract-brand-palette
  - Нет → уточнить цвета у пользователя или использовать нейтральную палитру
```

**Для image-based PDF:**
- `fitz.get_text()` вернёт пустую строку → это сигнал
- Контент: запросить у пользователя текстом или через OCR
- Палитра: pixel sampling через PyMuPDF (см. скилл `extract-brand-palette`)

### Шаг 5 — Архитектура генератора (если формат HTML→PDF)

Обязательные принципы:

```python
# 1. Data-template separation
#    Все данные — Python dicts/lists.
#    HTML — только в render-функциях. Никогда не мешать.

DATA = [{ "name": "...", "fields": {...} }]

def render_card(item): ...
def render_section(items): ...

# 2. Print CSS
@media print {
    .card { page-break-inside: avoid; }
    .section-cover { page-break-before: always; }
    body { font-size: 10pt; }
}

# 3. Encoding (Windows)
import sys
sys.stdout.reconfigure(encoding='utf-8')

# 4. Вывод
with open('output.html', 'w', encoding='utf-8') as f:
    f.write(html)
print("Done. Open in Chrome → Ctrl+P → Save as PDF (A4)")
```

**Инструкция пользователю после генерации:**
Chrome/Edge → открыть output.html → Ctrl+P → Destination: Save as PDF →
Paper: A4 → Margins: None или Minimum → Background graphics: ✓ → Save.
