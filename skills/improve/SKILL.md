# Skill: Improve

**Назначение:** Обновление скиллов на основе `~/.claude/reflection.md` и строки коррекции пользователя. Замыкает self-improving loop.
**Когда использовать:** После того как пользователь заполнил строку коррекции в `~/.claude/reflection.md`.
**Результат:** Обновлённые скиллы (с явным апрувом на каждое изменение) + обновлённый `~/.claude/skills/index.md`.

---

## PROCESS

### Шаг 1 — Прочитай входные данные

1. `~/.claude/reflection.md` — полностью (глобальный файл, не в папке проекта)
2. Строку коррекции пользователя — **это главный приоритет**, она переопределяет всё остальное
3. Текущие версии всех скиллов из секции "Предложения по улучшению"
4. `~/.claude/skills/index.md` — текущее состояние реестра

Если `~/.claude/reflection.md` не найден или строка коррекции пуста — сообщи и остановись:
```
~/.claude/reflection.md не найден / строка коррекции пуста.
Запусти Reflect Skill и заполни строку коррекции перед Improve.
```

### Шаг 1.5 — Анализ контекста перед изменениями

Перед тем как составлять план изменений — проверь контекст по каждому скиллу из "Предложения по улучшению":

1. **История изменений:** прочитай `~/.claude/skills/changelog.md` (если существует).
   Для каждого скилла из плана: сколько раз уже менялся? Что менялось последний раз?
   → Если скилл менялся 3+ раз за последние 5 циклов — это сигнал нестабильности. Отметь явно в плане.

2. **Повторяющийся ❌:** просмотри `~/.claude/reflection-*.md` (архив).
   Есть ли у этого скилла ❌ в предыдущих рефлексиях?
   → Если да — это повторяющийся паттерн, не точечная проблема. Предложи более глубокое изменение, не косметику.

3. **Конфликты:** сравни предложенное изменение с последней записью в changelog для этого скилла.
   Не отменяет ли новое изменение то, что только что было добавлено?
   → Если конфликт — покажи его явно перед diff: `⚠️ Конфликт с правкой от [дата]: [суть]`

Если `~/.claude/skills/changelog.md` не существует — пропусти пункт 1, переходи к пунктам 2-3.

Результат этого шага — **не текст пользователю**, а внутренний контекст для Шага 2.
Если найдены сигналы нестабильности или конфликты — отметь их в плане изменений.

---

### Шаг 2 — Составь план изменений

Составь список всех предложенных изменений из reflection.md.
Отсортируй по приоритету:
1. **Строка коррекции пользователя** — всегда первой
2. Трения со конкретными предложениями
3. Новые скиллы
4. Правки CLAUDE.md
5. Лишнее (упрощения)

Покажи план одним сообщением до любых изменений:

```
Предлагаю следующие изменения (в порядке приоритета):

1. [скилл/файл]: [суть изменения] ← строка коррекции
2. [скилл/файл]: [суть изменения]
3. [скилл/файл]: [суть изменения]

Применяю по одному, каждый раз жду подтверждения.
Начинаем с №1?
```

Дождись "да" / "продолжай" / "пропусти" перед первым изменением.

### Шаг 3 — Применяй изменения по одному

Для каждого изменения из плана:

**1. Покажи diff перед применением:**

```
── Изменение N/M: [скилл] ──────────────────────

БЫЛО:
[точная цитата из текущего файла]

СТАНЕТ:
[новый текст]

Причина: [одна строка из reflection.md]

Применить? (да / нет / изменить)
```

**2. Жди явного ответа:**
- `да` / `продолжай` / `apply` → применяй изменение
- `нет` / `пропусти` / `skip` → пропускай, переходи к следующему
- `изменить` + правка → применяй скорректированную версию
- любой другой ответ → уточни намерение, не угадывай

**3. После применения — подтверди и запиши в changelog:**
```
✓ [файл] обновлён.
```

Сразу после подтверждения — добавь строку в `~/.claude/skills/changelog.md`:
```
YYYY-MM-DD | [skill-name] | [суть изменения одной строкой] | [источник: строка коррекции / трение / новый скилл]
```
Если файл не существует — создай его с заголовком из шаблона перед записью.

**4. Переходи к следующему пункту плана.**

### Шаг 3б — Создание нового скилла (если в плане есть новые скиллы)

Если пункт плана = "создать новый скилл":

1. Покажи описание будущего скилла (название, назначение, когда использовать) — дождись "да"
2. Используй `skill-generator` для создания `~/.claude/skills/[name]/SKILL.md` по шаблону
3. После создания — добавь строку в `~/.claude/skills/index.md` (в нужную группу):
   ```
   | `[name]` | [назначение] | [теги] | 0 | ✅ Ready |
   ```
4. Подтверди:
   ```
   ✓ ~/.claude/skills/[name]/SKILL.md создан.
   ✓ index.md обновлён.
   ```

Не пропускай шаг с показом описания — пользователь должен подтвердить, что скилл нужен именно такой.

---

### Шаг 4 — Обнови ~/.claude/skills/index.md

После всех применённых изменений:

**Обязательно — счётчики использований:**
Возьми из reflection.md таблицу скиллов (с оценками ✅/⚠️/❌) — все упомянутые скиллы использовались в этой сессии. Увеличь их счётчик "Использований" в index.md на 1. Это не опциональный шаг — без него счётчики бессмысленны.

Дополнительно: если скилл получил `❌` — добавь пометку `⚠️ Review` рядом со статусом в index.md. Если скилл получал `❌` уже в предыдущем reflection (проверь архив `reflection-*.md`) — это повторяющийся сигнал, кандидат на приоритетный Improve.

**Остальное:**
- Обнови статус изменённых скиллов
- Добавь строки для новых скиллов если создавались
- Перенеси в архив если скилл был удалён

Покажи diff для index.md — тоже с подтверждением.

### Шаг 5 — Архивирование и финальный отчёт

**Автоматически** (без подтверждения) переименуй `~/.claude/reflection.md`:
→ `~/.claude/reflection-YYYY-MM-DD.md`  (дата берётся из заголовка reflection.md)

Это технический cleanup — не спрашивай разрешения.

Затем выведи финальный отчёт:

```
── Итог Improve сессии ─────────────────────────

Применено изменений:  N
Пропущено:            M
Файлы обновлены:
  ✓ ~/.claude/skills/[name]/SKILL.md
  ✓ ~/.claude/skills/index.md
Архив:
  ✓ ~/.claude/reflection.md → reflection-YYYY-MM-DD.md

Цикл завершён:
  intake → работа → reflect → improve ✓

Следующий проект начнётся с улучшенными скиллами.

[Если Применено изменений ≥ 1]:
  Новые улучшения готовы к экспорту → /sil-export
```

## ПРАВИЛА CURATOR

**Консерватизм изменений:**
- Предпочитай точечные правки переписыванию
- Не меняй то, что явно работало (секция "Помогло" в reflection.md)
- Если предложение из reflection.md конфликтует со строкой коррекции — строка коррекции побеждает

**Границы:**
- Не применяй изменения без явного "да"
- Не объединяй несколько изменений в одном diff — по одному
- Не трогай `CLAUDE.md` проекта (не этого проекта — внешнего) без явного указания
- Не удаляй скиллы — только архивируй (перемести в раздел "Архив" в index.md)

**При неопределённости:**
- Предложение из reflection.md размыто → уточни у пользователя перед показом diff
- Изменение затрагивает несколько скиллов → покажи все связанные diff'ы вместе
- Непонятно как реализовать строку коррекции → покажи 2 варианта, попроси выбрать

- [ ] `~/.claude/skills/index.md` обновлён — счётчики, статусы, архив
- [ ] Ни одно изменение не применено без явного "да"
- [ ] `~/.claude/reflection.md` архивирован автоматически в Шаге 5 (переименован в `reflection-YYYY-MM-DD.md`)
